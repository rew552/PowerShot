# PowerShot v3.2 — Responsive & Device-Independent UI Refactoring Plan

> **Plan ID:** 1778360958600-swift-mountain  
> **Goal:** Eliminate hardware/screen-resolution dependencies and deliver a consistent, responsive, device-independent UI/UX across all environments.  
> **Scope:** WPF XAML layouts, GDI+ rendering logic, HTML Viewer CSS/JS, and supporting controller code.  
> **Constraint:** Maintain .NET Framework 4.6+ / WPF compatibility (no .NET 8-only APIs in production runtime).

---

## Executive Summary

PowerShot v3.2’s UI layer relies heavily on **hard-coded pixel values** (window sizes, margins, paddings, font sizes, control dimensions) and its **GDI+ overlay renderer** uses absolute font/padding metrics regardless of image resolution. The HTML viewer uses fixed-width card and sidebar layouts without breakpoints. These design choices cause:

- **Clipping or overflow** on small screens / high-DPI laptops.
- **Inconsistent overlay readability** across 720p → 8K captures.
- **Unusable crop hit-zones** when a large image is scaled down inside a `Viewbox`.
- **Non-responsive HTML gallery** on narrow browser windows or mobile devices.

This plan defines **5 phases** of surgical refactoring to replace absolute metrics with **scalable, resolution-aware, and responsive** alternatives while preserving existing behavior and test coverage.

## Phase 1 — WPF XAML Layout Refactoring

### 1.1 MainWindow.xaml (`src/Views/MainWindow.xaml`)

| Current Issue | Target Amendment | Technical Step |
|---|---|---|
| Fixed `Width="1100" Height="650"` | **Dynamic initial sizing** capped to `SystemParameters.WorkArea` | In `MainWindowController`, after loading the window, compute `initialW = Min(1100, workArea.Width * 0.85)` and `initialH = Min(650, workArea.Height * 0.85)`. Remove fixed `Width`/`Height` from XAML; keep `MinWidth="720" MinHeight="480"` to support small tablets/laptops. |
| Fixed two-column `65* / 35*` | **Adaptive proportional layout with min-constraints** | Add `MinWidth="280"` to the right-column container (TabControl). If total window width drops below ~900 DIPs, allow horizontal scrolling inside the right panel rather than crushing the preview. Set `Grid.ColumnDefinitions` to `Auto` for the left preview border (constrained by available space) and `*` for the right panel. |
| Fixed label widths (`Width="70"`, `Width="50"`) | **Shared size group for form alignment** | Wrap form rows in a `Grid` with `Grid.IsSharedSizeScope="True"`. Use `SharedSizeGroup="LabelCol"` on label columns so labels size to content but remain aligned across rows. Remove hard `Width` values. |
| Fixed button sizes (`Width="36" Height="28"`, `Padding="22,4"`) | **DIP-relative sizing with touch minimums** | NavButton: change `Width="40" Height="36"` (≈ 40 DIPs is the accessibility minimum; 36 is acceptable for desktop-primary use). SecondaryButton: remove fixed `Height="28"`; use `MinHeight="32"` and `Padding="12,6"` for better touch/pen support. PrimaryButton: `MinHeight="36"` and `Padding="16,10"`. |
| Fixed `FontSize="13"` everywhere | **Theme-level font resources** | Define `SystemDouble` resources in `Window.Resources`: `<sys:Double x:Key="FontSizeBase">13</sys:Double>`, `<sys:Double x:Key="FontSizeSmall">12</sys:Double>`, `<sys:Double x:Key="FontSizeLarge">14</sys:Double>`. Bind all `FontSize` setters to these resources. This allows a single resource change to scale the entire UI. |
| GridView fixed column widths | **Auto-width with proportional fallback** | Set `GridViewColumn Width="Auto"` for both columns. In `MainWindowController.RefreshExplorer()`, keep the existing auto-resize logic but also set a `MaxWidth` on the first column based on `ListView.ActualWidth * 0.65` to prevent overflow. |
| Crop canvas visibility inside `Viewbox` | **Preserve aspect ratio without clipping** | Ensure the `Viewbox` parent uses `Stretch="Uniform"` (already done). Add `MaxWidth`/`MaxHeight` bindings to the parent `Border` so the preview never pushes the right column off-screen. |

**Implementation Detail — WorkArea Sizing (C#)**

In `MainWindowController.Initialize()` (or `ClipboardWatcher.ShowMainWindow()` before `Show()`):

```csharp
var area = SystemParameters.WorkArea;
_window.Width = Math.Min(1100, area.Width * 0.90);
_window.Height = Math.Min(650, area.Height * 0.90);
_window.Left = (area.Width - _window.Width) / 2;
_window.Top = (area.Height - _window.Height) / 2;
```

This guarantees the window never exceeds the available monitor real-estate, regardless of DPI scaling.

| Current Issue | Target Amendment | Technical Step |
|---|---|---|
| Fixed `Width="800" Height="600"` | **Fit-to-image with screen clamping** | Remove fixed `Width`/`Height`. **Implementation Detail — Preview Sizing (C#)**

In `PreviewLauncher.Show()`:

```csharp
double dpiScale = PresentationSource.FromVisual(owner)?.CompositionTarget?.TransformToDevice.M11 ?? 1.0;
int padX = 32, padY = 48; // chrome + title margin
double desiredW = (bi.PixelWidth / dpiScale) + padX;
double desiredH = (bi.PixelHeight / dpiScale) + padY;
var area = SystemParameters.WorkArea;
previewWindow.Width = Math.Min(desiredW, area.Width * 0.90);
previewWindow.Height = Math.Min(desiredH, area.Height * 0.90);
previewWindow.WindowStartupLocation = WindowStartupLocation.CenterOwner;
```

## Phase 2 — Rendering Engine Refactoring

### 2.1 OverlayRenderer.cs (`src/Utils/OverlayRenderer.cs`)

**Current Issue:** `FontSize = 16f` and `Padding = 12f` are constants. On a 3840×2160 screenshot the text is microscopic; on a 640×480 screenshot it is oversized.

**Amendment:** Make font size and padding **relative to the image bounds** with clamped min/max values.

**Technical Steps:**

1. Replace constants with a resolution-aware calculation:

```csharp
private const float FontSizeRatio = 0.022f;   // 2.2% of image height
private const float PaddingRatio = 0.015f;     // 1.5% of image height
private const float MinFontSize = 10f;
private const float MaxFontSize = 56f;
private const float MinPadding = 6f;
private const float MaxPadding = 32f;
```

2. In `Apply()`, compute:

```csharp
float refDim = Math.Min(bounds.Width, bounds.Height);
float fontSize = Math.Max(MinFontSize, Math.Min(MaxFontSize, refDim * FontSizeRatio));
float padding = Math.Max(MinPadding, Math.Min(MaxPadding, refDim * PaddingRatio));
```

3. Pass `fontSize` and `padding` into `DrawBlock` and `GetPosition`. Update `GetPosition` signature (or overload) to accept `padding` instead of relying on the constant.

4. **Test Impact:** `OverlayRendererTests.cs` hardcodes `Padding = 12f` and invokes the private `GetPosition`. After the refactor, `GetPosition` must accept a `float padding` parameter (or use a default). Update tests to pass `12f` explicitly for backward-compatible test cases, and add new test cases for scaled padding (e.g., bounds of 4000×3000 should produce a padding > 12).

### 2.2 CropController.cs (`src/Controllers/CropController.cs`)

**Current Issue:** `EdgeMargin = 8.0` is in **bitmap pixels**. When a 3840×2160 image is scaled down to fit a 500 DIP-wide preview, the 8px hit-margin becomes physically ~2px on screen, making resize handles nearly impossible to grab.

**Amendment:** Convert the hit-test margin from **screen DIPs to canvas logical pixels** dynamically.

**Technical Steps:**

1. Keep `EdgeMargin` as the desired **screen margin in DIPs** (e.g., `8.0` → increase to `12.0` for better usability).

2. In `HitTest(WpfPoint p)`, compute the canvas-to-visual scale factor:

```csharp
private double GetCanvasScale()
{
    if (_canvas == null || _canvas.Width == 0) return 1.0;
    // ActualWidth is the rendered size (after Viewbox scaling)
    return _canvas.ActualWidth / _canvas.Width;
}
```

3. Convert the constant DIP margin to canvas pixels:

```csharp
double scale = GetCanvasScale();
double edgeMargin = EdgeMargin / scale; // EdgeMargin stays 12 DIPs
```

4. Use `edgeMargin` in all `Math.Abs` comparisons inside `HitTest`.

5. **Cursor feedback:** `SetCursor` should also use the scaled margin so the cursor changes reliably when near a handle.

6. **Clamping in `ClampToCanvas`:** Ensure `ClampToCanvas` continues to operate in canvas (bitmap) coordinates; no change needed there.

## Phase 3 — HTML Viewer Responsive Refactoring

### 3.1 viewer_template.html (`src/Views/viewer_template.html`)

**Current Issue:** Sidebar is `width: 250px`, thumbnails are `width: 240px` with `height: 135px`, and there are no CSS media queries.

**Amendment:** Implement a **mobile-first responsive layout** using CSS Grid/Flexbox and media queries.

**Technical Steps:**

1. **Replace fixed sidebar width with CSS Grid:**

```css
body {
    display: grid;
    grid-template-columns: minmax(200px, 18vw) 1fr;
    height: 100vh;
}
@media (max-width: 768px) {
    body {
        grid-template-columns: 1fr;
        grid-template-rows: auto 1fr;
    }
    #sidebar { display: none; } /* Or transform into a collapsible hamburger menu */
}
```

2. **Replace fixed thumbnail card width with responsive `clamp()` and CSS Grid:**

```css
#gallery {
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
    gap: 16px;
    padding: 16px;
    align-content: start;
}
.thumb-card {
    width: 100%; /* Fill grid cell */
    min-width: 0; /* Prevent overflow */
}
.thumb-img {
    width: 100%;
    aspect-ratio: 16 / 9;
    object-fit: contain;
    height: auto; /* Remove fixed 135px */
}
```

3. **Touch-friendly lightbox buttons:**

```css
.lightbox-nav {
    width: 60px;   /* up from 50px */
    height: 120px; /* up from 100px */
    font-size: 28px;
}
#lightbox-close {
    width: 48px; height: 48px;
    top: 12px; right: 12px;
}
```

4. **Font scaling with `rem`:**

```css
html { font-size: 14px; }
@media (min-width: 1920px) { html { font-size: 16px; } }
@media (max-width: 480px)  { html { font-size: 12px; } }
```

5. **Toolbar wrapping:**

```css
.toolbar {
    flex-wrap: wrap;
    height: auto;
    min-height: 50px;
    padding: 8px 16px;
}
```

## Risk Assessment & Mitigation

| Risk | Mitigation |
|---|---|
| **WPF `Add-Type` compilation fails** because of new C# syntax (e.g., `?.`) | Stick to C# 5.0-compatible syntax in all source files; avoid null-conditional operators and string interpolation in files compiled by `PowerShot.ps1`. |
| **Reflection-based tests break** due to signature changes in `OverlayRenderer` | Update test projects immediately after changing private method signatures. Consider making `GetPosition` `internal` instead of `private` so tests can call it directly without reflection (requires `InternalsVisibleTo` or keeping it public-internal). |
| **Crop hit-test feels different** after scaling | Maintain the *screen* margin at 12 DIPs (was effectively ~8 DIPs before for large images). This is an improvement, but document the change in `CHANGELOG.md`. |
| **HTML viewer layout breaks** on older browsers (no `aspect-ratio` support) | Provide a fallback: `@supports not (aspect-ratio: 16/9) { .thumb-img { padding-top: 56.25%; position: relative; } }` or keep a `min-height`. The target is modern Edge/Chrome on Windows 10/11, so `aspect-ratio` is safe. |
